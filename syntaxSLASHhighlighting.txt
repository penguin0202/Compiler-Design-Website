But really, writing code is identical to writing words. I mentioned that the Operating System can "open the script in a text/code editor program like Notepad or Visual Studio Code to allow users to edit it". I deliberately chose to bundle the two programs because, aside from additional features from code editors, they can both edit code. Go ahead, try opening a language file in Notepad, you'll find that after editing it and saving, executing the file in Visual Studio Code still works with your updated code (unless you make a mistake, obviously). You can also try to create a ".txt" file, type in some code (with the correct syntax!), change it into a ".java" file and run it; you'll also find that your code runs perfectly fine. Since changing file extensions doesn't change the file contents (you can verify this by comparing the bytes of the before (.txt) and after (.java) files), code files are really just what you type in them, nothing else is added to the mix. What's the point of a "language file" then, you might ask, if text files are just the same. Well, it's to let the O.S. know to automatically open that file in a code editor rather than in a plain text editor. But why choose a code editor when a text editor can already do the job. Or rather, what's the benefit of using a code editor? That is a great question, and I've been dragging this paragraph too long to build up this reveal that will basically mean nothing without further elaboration in the second paragraph: the main attraction of code editors is SYNTAX HIGHLIGHTING!!!

You most likely encountered this feature if you had coded before, where a code editor color-codes a language script's syntax (its various "terms") such as keywords, variable names, and comments in a process called "syntax highlighting". Take Visual Studio Code and the Java language for example: keywords such as "if" and "while" might be colored in purple, variable names in light-blue, with comments highlighted in dark-green. The reason syntax highlighting exists is for the programmers to have an easier time reading code. How so? Well, a bit of a combination of three reasons:

First, scripts have different terms/words that serve different utilities. Keywords such as "if" and "while" mark how the resulting program is going to execute different parts of code; variable names represent a piece of memory on a computer; and datatypes such as strings (like "abcde") and integers (like 67) represent the actual data that is stored on computers. Elements like these culminate to a comprehensive programming language that can instruct computers to do things (borrowing from a future section), but each of their usages are quite distinct; in other words: they serve different duties on the computer.

Second, humans like to categorize different concepts. Humans, like you and I, have long needed categorizations of things to survive. Our brains distinguished edible food from inedible but otherwise-may-be-of-use substances, red hot fiery things from neutral or cold temperature-d things, friends from strangers, all to the end of helping us thrive in our environment. This biology/psychology touch-on will somewhat be relevant in later sections, but to bring it back to the topic at hand: humans divide things/concepts into groups because this allows us to understand them better.

Third, related to second, humans like to categorize things by color (no I don't mean it like that). If you have eyes and are not colorblind, or blind in general I guess, you have a pretty good chance at distinguishing objects based on their different hues (you can double-check me by testing if you can distinguish an object in front of a wall and the wall itself based on their color difference). Of course, there are other ways to categorize things; in a text file (finally I bring it back), instead of color, displaying different sizes and fonts of words could also be a way to grouping and differentiating them; however, these alternative approaches have major downsides: changing the size of certain terms require your eyes to move up and down to understand what's going on, which can massively frustrate developers and decrease productivity of producing code; and changing the fonts of words can be confusing or hard to understand when skimming through them (which would also decrease productivity of code). Color categorization on the other hand is unobtrusive to the reading of the code, and can allow developers to easily understand the different elements of the programing language at a glance.

So if I were to comprehensively pre-sum this bit-bloated section up, it would be that syntax highlighting allows developers to categorize the different elements of a programming language, elements which carry out different duties in instructing the computer to do different things, through color-coding, which is the best way of categorization for humans because of its uniformity and unobtrusiveness, thus making code easier to read and understand, which then means developers could write more good code.
