For those of you who are also puzzled, do not fret, for I am here to explain everything about the process! (with some additional inessential and you-might-already-know information that I want to rant about)


When a file is created on a computer, either by you or a program, its name usually ends with a file extension (e.g. ".docx" for Word documents, ".png" for P.N.G. images). But what exactly do the extensions do? Well, file extensions help the Operating System (like Microsoft's Windows or Apple's MacBook) identify how to open a file. Take ".docx" for example: when you open a file ending in the extension, the Operating System (O.S.) searches through its catalog of programs to find one that is designed to open a .docx document, then it calls the program to open it (in this case, Microsoft Word). If extensions had not existed, the computer would have no idea how to differentiate between image files like .pngs and executable files like .exe, thus making it hard to do anything on a computer that involves files (which are a lot of things). This idea of extensions can be extended (see what I did there?) to programming scripts as well. When opening a, let's say, C language file, the O.S. can either open the script in a text/code editor program like Notepad or Visual Studio Code to allow users to edit it, or it can open the file, per the user's request, in a program that can "run" the file (which is the end goal of a script). That program is called a "compiler". I will backtrack and make-accurate this in the following section, but for now this is all you need to know: a compiler is a program that allows code in a file to be executed on a computer.

Aren't programming language files different from plain text files? WNo, the answer is no. Ok now I'm going to blow all your minds out: every file is a text file. Now let me qualify that : everything *can* be a text file. What past me knew is true, computers store things in 1s and 0s. Then how are texts stored??? Well, they are't; they are really just *representations* of different 1s and 0s. In the ASCII table, every symbol (ok, English ones) can be mapped to a set of 1s and 0s (that are different from every other symbol's 1s and 0s). For example, the letter "A" can be 000000001, and the character "&" can be 00010011. Now I want to tagentlly refer to something else: a character's property is separate from its representation. Take the letter "O", if we somehow wrote the letter O like "╤", what would change? Well, the only thing that would change is how we write out the letter. The meaning of the letter O, as well as its compounds with other letters that form words would also not change. The only thing that changes is its representation. Now if wrote the letter O like "P" (like the letter P), what would change? well, words like hippo would become hippp, and then we wouldn't know how to pronounce it. So in a set of characters, the only thing that matters besides its property is its non-similarity as other characters in the set. This is what computers do--represent characters by assigning them a representation in 1s and 0s that differ from other characters' 1s and 0s.
