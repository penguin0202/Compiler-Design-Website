Assembly is, basically, machine code (which, remember, is not readable to humans when represented as text), that IS readable to humans (somewhat). Alright I'm making it more complicated that it is, let me rephrase: it is the last programming language in the chain of programming languages from high-level (think C and Python) to low-level (machine code) that is readable to humans (with itself classified as a low-level language). Whereas high-level languages use an English-like syntax, deal with memory in an abstract way, and contain quite understand-able control structures (if-else/while statements), low-level languages like Assembly and machine code use quite obscure abbreviations, deal with hardware memory directly, and use goto/jump instructions and labels to simulate human-understandable branches in code (code "branches" when, for example, the "if" condition is false and the "else" block code runs). Assembly, is just machine code translated, but not through direct byte-to-text, into English, basically.

Assembly code might look something like this (Assembly of the O.S. "Linux" version): 

1    section .data
2        msg db "Hello World!", 0xa
3        len equ $ - msg
4    section .text
5        global _start
6    _start: 
7        mov eax, 4
8        mov ebx, 1
9        mov ecx, msg
10       mov edx, len
11       int 0x80
12       mov eax, 1
13       xor ebx, ebx
14       int 0x80

This assembly program prints "Hello World!" to the console. Contrast that with C's version:

Assembly, while longer than other languages, is better described as more "expressive". The exemplary instance being the use of registers and system calls, as opposed to C's "printf" function. But before I get into that, let's talk about what those two things are.

Registers are special pieces of memory right inside the CPU that it can access super-duper quickly that has two important qualities in the context of compilers:
1. It is the basis of pretty much all computation. If you need to add two numbers and put the result somewhere else, you have to load the number from your memory address #1 into a register, load number from memory address #2 into another register, then tell the CPU to add the two registers together, which will put the result in the first register, then you'd have to copy the number at that register to the memory address you want to store the number at.
2. It is a way for Operating Systems to know what kind of "system calls" it should do. System calls are basically a piece of software asking the Operating System to perform kernel-level (system-level) actions, such as reading from and writing to any console, specific memory addresses (besides registers), and files, and controling other hardware devices (kernel-level basically means unrestricted access to any and all computer components). And the way the O.S. knows what KIND of system call we want to perform, whether that's a print-to-console call, or an exit call (which, you guessed it, exits the program; it is a system call because the O.S. needs to know when it can reclaim the program's now-unused resources (memory)) is by the numbers inputted into select registers. For example, the "print" system call requires the "eax" register to be 4, the "ebx" register to be 1, "ecx" register to contain the memory address of where the actual string of what is to be printed, and register "edx" to be the length of the string. Then we write in a new line, "int 0x80", which will "int"errupt the program's execution, allow the O.S. to switch into kernel-mode, read the inputs from the registers, determine what kind of system call to execute, then finally execute it, printing the inputted string (as is the case in the assembly "hello world" program above, under the ".text" section; as you might have guessed, then, that "mov" was an instruction that tells the computer to put the second argument value into the first address). And for another example, to "exit" a program, we'd put 1 into the "eax" register, and 0 into register "ebx", then do the system call. It is worth noting that different Operating Systems have different system call methods. For Linux, "int 0x80" is the way to go; for Windows, simply write "syscall". It is also a given, then, that different Systems require different numbers to be put into registers to achieve the same desired system call (elaborate?). (side note: the Assembly language can call the O.S. since it is low-level, and will be directly translated into machine code, which definitely can interact with the Operating System)
