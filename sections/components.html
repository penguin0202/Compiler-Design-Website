Components/of a Language

Now we're really going to get into designing a programming language. And the way we'll do that is to look at how existing programming languages, well, do what they do. But not their keywords or their datatypes, first, we'll actually look at their spaces.

Just like in English, and the majority of natural human languages, there needs to be a way to separate words/concepts from one another, in order for the composed sentences to have meaning/make sense. Spaces, or rather, whitespaces, is thus the most obvious choice to help do so (I don't think I need to substantiate this). In programming languages, which are built for human reading of computer instructions, whitespaces are especially important to separate things like names from other components of the language, lest wrong, or even disasterous, code executed. For example, "int myVariable = 5;" in C is vastly different from "intmyVariable = 5;"; the former declares an integer variable called myVariable and initializes it to 5 (probably the intended code), while the latter assigns the value of 5 to an existing variable (if only properly declared before this line), which can be assumed to be an integer one, named "intmyVariable" (probably isn't the intended behavior).

But you may have noticed that some "things" don't need spaces to differentiate itself from other parts/components of the language, like semicolons, commas in function call arguments list, or equal signs; I could have done that above. I would again point to writing--the words I'm writing on right now, the punctuation marks, like commas, dashes, quotations, parenthesis, and periods, all don't need to have a space before, or really after, them. This is because words that make up "meaning", like "words", "that", "make", "up", and "meaning", are guranteed to just be comprised of letters. So since programming languages are modeled after natural languages, 'tis the same--anytime a symbol appears, it will never be assumed to be part of the previous set of characters, thus no need for white spaces.

Some might understand that semicolons ';' and commas ',' are represented using symbols, because they don't have traditional "meanings", they serve more of a delimeter (separator) role in writing and thus in programming (former for new line, latter for list items). But some might question why the "assign" concept in programming ('='), or the "add" operator ('+'), or the "divide by" ('/'), "or "less than" ('<'), the "not" operator ('!'), etc. are not written out using the actual word, but instead mere symbols, despite having "meaning".
