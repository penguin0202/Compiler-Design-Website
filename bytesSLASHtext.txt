At the hardware level, everything is just teeny-tiny on and off switches. Everything, ranging from documents to video files to apps. At the software level, we call these on and off switches "ones and zeroes"; binary, if you want to be fancy.

So then how do programs display and do vastly different things just based on a bunch of ones and zeroes? 

Zooming on text specifically: I highlighted before that you could compare the bytes between scripts and text files to see if they are really the same. But how do bytes get turned into words in the first place? The answer, more broadly and what I want you to take away from this section, is the idea of "interpretation" (or I might use the word "representation").

The actual answer to that question is through a concept called the "ASCII Table". A.S.C.I.I., or its un-acronym-ed version, "American Standard Code for Information Interchange", is a conversion table that that translates bytes (8-bits) into a respective textual character (letters like 'a'). Creation led by an International Business Machines Corporation (IBM; a very large tech company back in the day) engineer, its purpose is to allow for (English) characters--letters (capitalized and not), numbers, punctuation, miscellaneous symbols, spaces, and line breaks (have to represent newline somehow)--to be mapped to a set of electronic signals a computer can store, and thus communicate with. Think of it as a successor to morse code for computers: whereas 3 dots followed by 3 long dashes and then another 3 dots [...------...] translates to "SOS" in morse code, the byte sequence "01010011", followed by "01001111", and then another "01010011" in binary spells out the same thing in ASCII (a help signal!). By assigning different bytes to different characters, the computer could then decide, well, what characters to display using those bytes as input.

The logic of the computer sort of goes like: "if inputted byte needing to be drawn as a character is 01100001...let's check the ASCII table I have here...oh it's the letter 'a'! Then put pixels on the screen in the shape of an A at the specified position on the screen (communicates that information to the display monitor), adjusted for font, color, and size of course".

Why are specific bytes plotted to specific characters, you may ask? They have their reasons; for example, capitalized letters are one bit switch away from each other ('A' is 01000001, and 'a' is 01100001) to allow for easy conversion, and control characters (null character, space, tabs, new line, carriage return, page break (deprecated, mostly), etc) are placed near the top (near byte "00000000") to distinguish them from "regular" characters to avoid confusion. (I encourage you to explore the intended ordering of ASCII, as I find it a fascinating history)

Originally used for teletypewriters, ASCII is now widely used in modern computers to "encode" characters (character encoding just means "encrypting" characters into another form, in this case, binary). But it is important to note that the ASCII table ONLY encodes English-adjacent characters; Chinese symbols and Arabic words, for example, have no way of being represented in binary, both because in history, ASCII was only intended for American/European communication, and that the total distinct combinations of a byte, 256, is not enough to encompass every character from all across the world (for reference: the world has over 7000 separate languages with their own unique words and symbols in writing). So...how does one solve this? (side note: I feel obligated to note that accurately representing every language's symbols is mandatory if we want to live in a fair world under the Internet) We solve it by...creating another character conversion table that translates into more than just one byte! That character encoding system is called "Unicode"! If you had ever used emojis before, you may be familiar with the term "unicode". Unicode is basically an (exaggeratively exponentially) extended ASCII table that (theoretically) allows every language's character, accented or otherwise (like 'ú' or '和'), emoji (like '😍'), and mathematic symbol (like '√') to be mapped to a set of bytes; 1 to 4 of them depending on the encoding "method". If you'd ever typed in Microsoft's Windows 11 Notepad, or made a website using HTML, you might come across a thing called "UTF-8". "UTF-X" is an encoding method for Unicode that decides how many bits (X number of them) is (minimally) used to represent one character (up to use of 4 bytes). UTF-8 means a single character can be represented from 1 byte to 4 bytes (8 bits to 32 bits), depending on what kind of character it is: if a character is an English character in the range of ASCII, the encoding will just use one byte on that character; but if a character is beyond the ASCII range, in this example, the mathematical symbol 'π' (Pi), it'll use what's called a "variable-length encoding" method to store that character in 2 bytes [11001111 10000000]. Variable-length encoding is, fundamentally, using some bits in the first byte as a "flag" that signals whether the next (continuing) byte is part of an overarching data-set; in this case, the "Pi" character in UTF-8 (what I said is technically wrong, but hopefully the "idea" of a "flag" sticks; I recommend correcting me). The "UTF-8" unicode encoding method is primarily used in text files and websites because of its capacity to be both minimalistic (you can store textual symbols with just one byte since it's just ASCII), AND maximalistic (you can store on non-ASCII symbol using up to 4 bytes using variable-length encoding). The reason there's a maximum for UTF encoding for Unicode is that there just isn't a point to allow for characters to be stored using more than 4 bytes; disregarding UTF-8 nad UTF-16's need for variable-length encoding flag bits (thus reducing the number of bits usable to "represent" a character), UTF-32, which uses exactly 32 bits (4 bytes) to represent every single character, can already store up to a whopping 4,294,967,296 characters (2^32), well over what we as humans need to....well do anything, really. And that's not to mention (but I am mentioning it) that the Unicode conversion table itself only defines up to 1,114,112 characters (the reality of the Unicode dataset is much more complicated, but this is the gist). [aside: if you want to type your own unicode characters on Windows, you could hold the "alt" key and press four numbers on your keyboard's numpad, and voilà]

Remember when I said ASCII uses one byte, A.K.A 8 bits, to store text characters? Well, that's not *technically* accurate. It only uses 7 bits. ??? Why is that? It's because the people who created the conversion standard just...didnt need any more. 7 bits was more than enough to represent English letters, numbers, and then some (though not literally accurate, one could say ASCII is just "Unicode UTF-7 but "fixed-length" (as opposed to variable-length encoding; just like UTF-32)" because it uses 7-bits). So why are they stored in a byte, which is 1 bit more than ASCII needed to translate all its characters? Well, it's because the byte is the smallest block of memory programs are allowed to store, manipulate/do operations on at one time on a computer. Computer engineering companies are popping in and out of the market, and each of them have different ideas about how to "bundle" data: some thought a group of 4 bits would be sufficient because that's enough to represent all numeral digits (2^4=16 bits could encompass numbers 0-9), some thought 5 bits would be better because it allowed for the addition of negative signs, some thought 6 bits were extra-ly better because it was divisible by two, which would be easier to work with in biary, and some thought 12 bits were more useful because it allowed the storage of two English characters (only capitalized or in-lowercase letters though, can't do both, because the 2^6=64 is only 12 available character codes more than 26*2=52 letters, and we'll still need to add in digits, punctuation, and other control characters) in one "group". Having the "norm" for the "smallest addressable unit of memory" established in the Computer Science field was revolutionary, and so IBM manufactured its computers using the 8-bit model ("sweet spot", as some woudl call it, because ASCII is 7-bits and because multiples of two is just generally better to work with when computing, thus the closest bit-number to 7, 8), and this became the convention all the way to this day.
