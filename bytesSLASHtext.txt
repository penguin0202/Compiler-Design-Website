The actual answer to that question is through a concept called the "ASCII Table". A.S.C.I.I., or its un-acronym-ed version, "American Standard Code for Information Interchange", is a conversion table that that translates bytes (8-bits) into a respective textual character (letters like 'a'). Creation led by an IBM engineer, its purpose is to allow for (English) characters--letters (capitalized and not), numbers, symbols, spaces, and line breaks (have to represent newline somehow)--to be mapped to a set of electronic signals a computer can store, and thus communicate with. Think of it as a successor to morse code for computers: whereas 3 dots followed by 3 long dashes and then another 3 dots [...------...] translates to "SOS" in morse code, the byte sequence "01010011", followed by "01001111", and then another "01010011" in ASCII spells out the same thing (a help signal!). By assigning different bytes to different characters, the computer could then decide, well, what characters to display using those bytes as input.

The logic of the computer sort of goes like: "if inputted byte needing to be drawn as a character is 01100001...let's check the ASCII table I have here...oh it's the letter 'a'! Then put pixels on the screen in the shape of an A at the specified position on the screen (communicates that information to the display monitor), adjusted for font, color, and size of course".

Why are specific bytes plotted to specific characters, you may ask? They have their reasons; for example, capitalized letters are one bit switch away from each other ('A' is 01000001, and 'a' is 01100001) to allow for easy conversion, and control characters (null character, space, tabs, new line, carriage return, page break (deprecated, mostly), etc) are placed near the top (near byte "00000000") to distinguish them from "regular" characters to avoid confusion. Originally used for teletypewriters, ASCII is now widely used in modern computers to "encode" characters (character encoding just means "encrypting" characters into another form, in this case, binary). But it is important to note that the ASCII table ONLY encodes English-adjacent characters; Chinese symbols and Arabic words, for example, have no way of being represented in binary, both because in history, ASCII was only intended for American/European communication, and that the total distinct combinations of a byte, 256, is not enough to encompass every character from all across the world (for reference: the world has over 7000 separate languages with their own unique words and symbols in writing). That character encoding system is called "Unicode"! If you had ever used emojis before, you may be familiar with the term "unicode". Unicode is basically a (exaggeratively exponentially) extended ASCII table that (theoretically) allows every language's character, accented or otherwise (like 'ú' or '和'), emoji (like '😍'), mathematic symbol (like '√') to be mapped to a set of bytes, 1 to 4 of them depending on the encoding "method". If you'd ever typed in Microsoft's Windows 11 Notepad, or made a website using HTML, you might come across a thing called "UTF-8". "UTF-X" is an encoding method for Unicode that decides how many bits (X number of them) is (minimally) used to represent one character (up to use of 4 bytes). UTF-8 means a single character can be represented from 1 byte to 4 bytes (8 bits to 32 bits), depending on what kind of character it is: if a character is an English character in the range of ASCII, the encoding will just use one byte on that character; but if a character is beyond the ASCII range, in this example, the mathematical symbol 'π' (Pi), it'll use what's called a "variable-length encoding" method to store that character in 2 bytes [11001111 10000000]. Variable-length encoding is, fundamentally, using some bits in the first byte as a "flag" that signals whether the next (continuing) byte is part of an overarching data-set; in this case, the "Pi" character in UTF-8 (what I said is technically wrong, but hopefully the "idea" of a "flag" sticks; I recommend correcting me). The "UTF-8" unicode encoding method is primarily used in text files and websites because of its capacity to be both minimalistic (you can store ASCII symbols with just one byte), AND maximalistic (you can store on non-ASCII symbol using up to 4 bytes). The reason there's a maximum for UTF encoding for Unicode is that there just isn't a point to allow for characters to be stored using more than 4 bytes; disregarding UTF-8 nad UTF-16's need for variable-length encoding flag bits (thus reducing the number of bits usable to "represent" a character), UTF-32, which uses exactly 32 bits (4 bytes) to represent every single character, can already store up to a whopping 4,294,967,296 characters (2^32), well over what we as humans need to....well do anything, really.
